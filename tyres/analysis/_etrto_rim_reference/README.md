# ETRTO Rim Reference Overlays

Generated from `input/ETRTO-Standards-Manual2017.pdf` for Tyre Designer rim-contour checks.

- `etrto_R8_diagram.png`, `etrto_R11_diagram.png`: rendered bitmap crops from ETRTO pages R.8 and R.11.
- `etrto_R8_bitmap_overlay.png`, `etrto_R11_bitmap_overlay.png`: schematic bitmap overlays regenerated by `../../tools/build_tyre_designer_etrto_rim_artifacts.py`. R.8 uses the basic non-hump rim contour; R.11 uses the H-hump plus adjacent bead-seat continuation. These are visual aids only; they place the current generated Tyre Designer geometry over the scanned ETRTO drawings with a fitted image transform and embed the current source HTML hash in the SVG.
- `etrto_bitmap_alignment_metrics.json`: reproducible pixel-distance diagnostics for the current scan overlays. High residuals mean the scan registration is still diagnostic, not a completed exact bitmap overlay proof.
- `rim_fit_points.json`: exported Tyre Designer rim geometry used by overlay generation.
- `etrto_rim_sweep_verification.json`: R.8/R.11 dimensional verification across standard rim width/diameter cases and diagnostic override stress cases.

The bitmap detail drawings are not rendered at strict millimetre scale, so the hard pass/fail check is `../etrto_rim_overlay_check.html`, which reports the dimension-true R.8/R.11 errors in millimetres/degrees.
`../tyre_designer_display_rim_overlay.html` and `../tyre_designer_display_rim_overlay.png` render the same visible rim layers used by the Tyre Designer plot over the independent R.8/R.11 reference curve.
The reproducible command-line gate is:

```powershell
python tyres/tools/build_tyre_designer_etrto_rim_artifacts.py
python tyres/tools/test_tyre_designer_etrto_rim_runtime.py
python tyres/tools/test_tyre_designer_etrto_rim_artifacts.py
```
